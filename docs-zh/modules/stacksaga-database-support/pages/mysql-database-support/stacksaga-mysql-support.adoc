= StackSaga MySQL 响应式支持 (MySQL Reactive Support)

== 概述 (Overview)

`stacksaga-mysql-reactive-support` 是 xref:stacksaga-database-support:overview/database-support-overview.adoc[数据库支持模块] 的 **MySQL 响应式（非阻塞 R2DBC）** 实现。
它为 StackSaga 引擎提供了访问 MySQL 数据库所需的一切底层能力，同时也暴露了内置端点，供 xref:trace-window:stacksaga-trace-window.adoc[] 控制台查询事件存储中的事务追踪明细。

NOTE: 请先阅读 xref:stacksaga-database-support:overview/database-support-overview.adoc[]，以便更好地理解数据库支持模块的职责与核心架构。

[[adding-mysql-support]]
=== 添加 `stacksaga-mysql-reactive-support` 依赖

请按以下方式将该依赖添加到您现有的编排器 (Orchestrator) 应用程序中：

.在 pom.xml 中添加 `stacksaga-mysql-reactive-support` 依赖
[source,xml,subs="attributes+"]
----
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.stacksaga</groupId>
            <artifactId>stacksaga-bom</artifactId>
            <version>{stacksaga-version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>
<dependency>
    <groupId>org.stacksaga</groupId>
    <artifactId>stacksaga-mysql-reactive-support</artifactId>
</dependency>
----

IMPORTANT: 推荐使用 http://init.stacksaga.org/[StackSaga Initializer (初始化器)] 获取项目所需的 StackSaga 依赖配置代码段，以确保拥有匹配正确的依赖版本和配置。

[[mysql-partitioning-maintenance]]
== 数据表分区维护 (Table Partition Maintenance)

MySQL 事件存储表（`es_transaction` 与 `es_transaction_execution_tryout`）采用基于 `created_at` 的范围分区 (Range Partitioning)，以确保在高并发写入下保持极快的插入速度和索引性能。

要自动创建未来日期的新分区，而无需将 DDL 执行权限耦合到各业务微服务实例中，请参阅专门的 xref:sql-database-support/stacksaga-sql-partition-support.adoc[StackSaga SQL 数据库分区支持] 模块。您可以将其独立部署一次，集中式统一管理所有 MySQL 和 PostgreSQL 数据库的分区生命周期。
