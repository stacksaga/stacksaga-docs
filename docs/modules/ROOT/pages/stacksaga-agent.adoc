== Overview

StackSaga includes a dedicated *Retry Subsystem* that handles asynchronous retrying of transactions that have been paused due to transient failures (e.g., network issues, temporary unavailability of downstream services).

The Retry Subsystem uses a three-component architecture — *Retry-Coordinator-Master*, *Retry-Coordinator-Slave*, and *Orchestrator (Retry-Node)* — to safely distribute retry responsibility across a cluster of microservice instances using token ring partitioning and RSocket communication.
