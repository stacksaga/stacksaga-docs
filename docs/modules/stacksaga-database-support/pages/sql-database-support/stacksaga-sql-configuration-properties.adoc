== Configuration Properties

The connection, connection-pool, transaction recovery, and recovery-node streaming properties below are bound by dialect-neutral configuration classes shared across every `stacksaga-*-reactive-support` SQL module — xref:mysql-database-support/stacksaga-mysql-support.adoc[MySQL], xref:oracle-database-support/stacksaga-oracle-support.adoc[Oracle], xref:postgresql-database-support/stacksaga-postgresql-support.adoc[PostgreSQL], and any other SQL dialect added in the future:

* `stacksaga.datasource.*` configures the dedicated reactive R2DBC connection factory and connection pool for the event store.
* `stacksaga.sql.transaction.recovery.*` configures transaction retry delay, crash-restore delay, and transaction lifetime per saga domain entity (with global defaults).
* `stacksaga.transaction.recovery-node.*` tunes the reactive streaming pipeline when the orchestrator instance operates as a xref:retry-ring-coordinator:transaction-retrying-with-retry-coordinator.adoc#orchestrator-deployment-modes[Retry-Node]. This pipeline is only active when enabled via xref:retry-ring-coordinator:ring-coordinator-connector.adoc#common_configuration_properties[`stacksaga.coordinator.connector.enabled=true`] (which defaults to `false`).

|Property Name|Default Value|Type|Description

|`stacksaga.datasource.enabled`|`true`|`boolean`| Enable or disable the starter entirely. Defaults to true so it activates automatically when added.

4+|*The following `stacksaga.datasource.r2dbc.*` properties configure the R2DBC connection used by the reactive event-store (read/write operations against the event store).*

|`stacksaga.datasource.r2dbc.url`|`-`|`String`| The R2DBC connection URL used by the event-store, e.g. `r2dbc:mysql://host:3306/database` or `r2dbc:oracle://host:1521/service_name`. If set, takes precedence over the individual host/port/database settings.
|`stacksaga.datasource.r2dbc.host`|`localhost`|`String`| The database server host for the reactive event-store connection.
|`stacksaga.datasource.r2dbc.port`|`3306`|`int`| The database server port for the reactive event-store connection. Override this for non-MySQL dialects (e.g. `1521` for Oracle's listener), or supply `stacksaga.datasource.r2dbc.url` instead.
|`stacksaga.datasource.r2dbc.database`|`-`|`String`| The database/service name used by the event-store via R2DBC.
|`stacksaga.datasource.r2dbc.username`|`-`|`String`| The username for the event-store's R2DBC connection.
|`stacksaga.datasource.r2dbc.password`|`-`|`String`| The password for the event-store's R2DBC connection.
|`stacksaga.datasource.r2dbc.connect-timeout`|`10s`|`Duration`| The maximum time to wait while establishing an event-store connection to the database server.
|`stacksaga.datasource.r2dbc.options`|`-`|`Map<String,String>`| Additional R2DBC driver-specific connection options for the event-store, as key-value pairs.
|`stacksaga.datasource.r2dbc.pool.initial-size`|`5`|`int`| The number of connections to create in the event-store's connection pool on startup.
|`stacksaga.datasource.r2dbc.pool.max-size`|`20`|`int`| The maximum number of connections allowed in the event-store's connection pool.
|`stacksaga.datasource.r2dbc.pool.max-idle-time`|`30m`|`Duration`| The maximum time a connection may remain idle in the event-store's pool before being closed.
|`stacksaga.datasource.r2dbc.pool.max-life-time`|`1h`|`Duration`| The maximum lifetime of a connection in the event-store's pool before it is closed and replaced.
|`stacksaga.datasource.r2dbc.pool.max-acquire-time`|`10s`|`Duration`| The maximum time to wait when acquiring a connection from the event-store's pool before failing.
|`stacksaga.datasource.r2dbc.pool.validation-query`|`SELECT 1`|`String`| The query used to validate an event-store connection before it is handed out from the pool.

4+|*The following `stacksaga.sql.transaction.recovery.*` properties control transaction retry, crash-restore, and transaction lifetime for the event-store, configurable with global defaults and overridable per saga domain entity.*

|`stacksaga.sql.transaction.recovery.default.retry.delay`|`1m`|`Duration`| Default duration a transaction is kept waiting before it is next exposed for retrying, avoiding frequent retries within a short time window.
|`stacksaga.sql.transaction.recovery.default.restore.delay`|`5h`|`Duration`| Default duration a transaction may remain without updates before it is considered crashed (e.g. ungraceful pod/application crash) and is restored for retrying.
|`stacksaga.sql.transaction.recovery.default.lifetime`|`24h`|`Duration`| Default maximum duration a transaction stays live in the event store. After this period it is quarantined and will not be re-exposed for recovery even if still in a processing state.
|`stacksaga.sql.transaction.recovery.<domain-name>.retry.delay`|`-`|`Duration`| Per-domain retry delay override (e.g. `order-domain`). Falls back to `default.retry.delay` if unset.
|`stacksaga.sql.transaction.recovery.<domain-name>.restore.delay`|`-`|`Duration`| Per-domain crash restore delay override (e.g. `order-domain`). Falls back to `default.restore.delay` if unset.
|`stacksaga.sql.transaction.recovery.<domain-name>.lifetime`|`-`|`Duration`| Per-domain transaction lifetime override (e.g. `order-domain`). Falls back to `default.lifetime` if unset.

4+|*The following `stacksaga.transaction.recovery-node.*` properties configure the reactive batch-fetch and streaming pipeline. These properties apply only when the orchestrator instance is enabled as a xref:retry-ring-coordinator:transaction-retrying-with-retry-coordinator.adoc#orchestrator-deployment-modes[Retry-Node] via xref:retry-ring-coordinator:ring-coordinator-connector.adoc#common_configuration_properties[`stacksaga.coordinator.connector.enabled=true`].*

|`stacksaga.transaction.recovery-node.batch-size`|`100`|`int`| Controls how many transactions are fetched from the database at once into the in-memory buffer (Reactor `limitRate` high tide). A higher value reduces database round trips but increases memory usage.
|`stacksaga.transaction.recovery-node.refill-threshold`|`75`|`int`| Controls when the framework triggers the next database fetch to refill the buffer (Reactor `limitRate` low tide). When the buffered count drops to this threshold, a background fetch is triggered so processing never stalls. Should always be less than `batch-size` (recommended ~75%).
|`stacksaga.transaction.recovery-node.concurrency`|`8`|`int`| Controls how many transactions are processed concurrently in the recovery pipeline (Reactor `flatMap` concurrency). Must stay within 50–70% of the recovery connection pool size to avoid connection starvation.
|`stacksaga.transaction.recovery-node.pre-fetch`|`4`|`int`| Controls how many transactions are pre-fetched and buffered in memory before processing begins (Reactor `flatMap` prefetch), improving throughput and reducing latency between batches.

=== Recovery Configuration Examples

StackSaga provides built-in defaults under `stacksaga.sql.transaction.recovery.default.*` and allows per-domain-entity overrides (e.g., `order-domain`) with automatic fallback to the default settings when a specific property is not configured for that domain:

.Example `application.properties`
[source,properties]
----
# Built-in defaults (applied across all saga domains)
stacksaga.sql.transaction.recovery.default.retry.delay=1m
stacksaga.sql.transaction.recovery.default.restore.delay=5h
stacksaga.sql.transaction.recovery.default.lifetime=24h

# Per-domain overrides (e.g. for "order-domain")
stacksaga.sql.transaction.recovery.order-domain.retry.delay=10s
stacksaga.sql.transaction.recovery.order-domain.restore.delay=1h
stacksaga.sql.transaction.recovery.order-domain.lifetime=12h
----

.Example `application.yml`
[source,yaml]
----
stacksaga:
  sql:
    transaction:
      recovery:
        default:
          retry:
            delay: 1m
          restore:
            delay: 5h
          lifetime: 24h
        order-domain:
          retry:
            delay: 10s
          restore:
            delay: 1h
          lifetime: 12h
----

=== Recovery-Node Pipeline Configuration Examples

By default, all orchestrator instances run as **Standard-Nodes** (`stacksaga.coordinator.connector.enabled=false`) and do not process recovery tasks. To turn an instance into a dedicated xref:retry-ring-coordinator:transaction-retrying-with-retry-coordinator.adoc#orchestrator-deployment-modes[Retry-Node], add the `stacksaga-ring-coordinator-connector` dependency and set xref:retry-ring-coordinator:ring-coordinator-connector.adoc#common_configuration_properties[`stacksaga.coordinator.connector.enabled=true`]. The `stacksaga.transaction.recovery-node.*` properties then tune the reactive batch-fetch and concurrency pipeline:

.Example `application.properties` (Retry-Node instance)
[source,properties]
----
# Enable this instance as a Retry-Node in the retry ring architecture
stacksaga.coordinator.connector.enabled=true

# Recovery-Node streaming and concurrency tuning
stacksaga.transaction.recovery-node.batch-size=100
stacksaga.transaction.recovery-node.refill-threshold=75
stacksaga.transaction.recovery-node.concurrency=8
stacksaga.transaction.recovery-node.pre-fetch=4
----

.Example `application.yml` (Retry-Node instance)
[source,yaml]
----
stacksaga:
  coordinator:
    connector:
      enabled: true # Enable Retry-Node mode
  transaction:
    recovery-node:
      batch-size: 100
      refill-threshold: 75
      concurrency: 8
      pre-fetch: 4
----
