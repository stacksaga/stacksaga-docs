= StackSaga TraceWindow Connector Overview

== Overview

The *StackSaga TraceWindow Connector* is the embedded library that enables your orchestrator microservices to securely communicate with the xref:stacksaga-trace-window.adoc[StackSaga TraceWindow] console.

It exposes the internal `/stacksaga/*` REST management endpoints, enforces dual-token security policies, supports optional secondary port and TLS isolation, and extracts execution logs from your local transaction event stores.

'''

== Key Capabilities

* **Universal Event-Store Access:** Exposes standardized internal endpoints for TraceWindow to fetch saga transaction traces from any xref:stacksaga-database-support:overview/database-support-overview.adoc[supported database implementation].
* **Dual Stack Support:** Provides specialized, native connectors for both **Spring MVC** (Servlet stack) and **Spring WebFlux** (reactive stack).
* **Dual Security Operating Modes:** Supports tokenless access for local development (`secure-api=false`) and dual-token validation with xref:stacksaga-trace-window.adoc#manage_operators[StackSaga Central RBAC] for production (`secure-api=true`).
* **Port & SSL Isolation:** Allows running trace endpoints on a dedicated secondary port with custom TLS certificates via Spring Boot SSL bundles.
* **Topological Agility:** Supports both xref:stacksaga-trace-window.adoc#direct_mode[Direct Mode] (`{host:port}/{api-path}`) and xref:stacksaga-trace-window.adoc#gateway_mode[Gateway Mode] (`{host:port}/{service-name}/{api-path}`) with automated CORS handling.

'''

== Adding the Connector Dependency

To integrate TraceWindow with your orchestrator service, add the dependency matching your web stack to your `pom.xml`:

* xref:#connector-servlet[`stacksaga-trace-window-connector-servlet`] — for services built with **Spring MVC** (Servlet stack).
* xref:#connector-webflux[`stacksaga-trace-window-connector-webflux`] — for services built with **Spring WebFlux** (reactive stack).

[NOTE]
====
Both dependencies automatically pull in `stacksaga-trace-window-connector-api` transitively. You only need to declare one connector dependency based on your chosen web runtime.
====

[#connector-servlet]
=== `stacksaga-trace-window-connector-servlet` (Spring MVC)

For standard Spring Boot Web (Tomcat/Jetty/Undertow) applications:

[source,xml]
----
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.stacksaga</groupId>
            <artifactId>stacksaga-bom</artifactId>
            <version>1.0.0-SNAPSHOT</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

<dependencies>
    <!-- StackSaga TraceWindow Connector for Spring MVC -->
    <dependency>
        <groupId>org.stacksaga</groupId>
        <artifactId>stacksaga-trace-window-connector-servlet</artifactId>
    </dependency>
</dependencies>
----

[#connector-webflux]
=== `stacksaga-trace-window-connector-webflux` (Spring WebFlux)

For reactive, non-blocking orchestrator services running on Netty:

[source,xml]
----
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.stacksaga</groupId>

    </dependency>
</dependencies>

== Configuration Properties Reference

All connector properties are bound from the `stacksaga.trace-window` configuration prefix.

[cols="3,1,1,4",options="header"]
[.properties-table.google-anno-skip]
|===
| Property
| Data Type
| Default Value
| Description

| `stacksaga.trace-window.enable-api`
| `boolean`
| `false`
| Master switch that exposes the local `/stacksaga/*` endpoints. Must be set to `true` for the connector to register filters and endpoints. When `false`, no endpoints are activated.

| `stacksaga.trace-window.secure-api`
| `boolean`
| `true`
| When `true` (default), incoming requests must carry a valid token matching `access-token`. In production, this validates against StackSaga Central. Set to `false` for local offline testing.

| `stacksaga.trace-window.access-token`
| `String`
| _(none)_
| The Service Access Token used to authenticate requests. Required when both `enable-api` and `secure-api` are `true`. Generated via xref:stacksaga-trace-window.adoc#generate_service_token[TraceWindow Project Settings].

| `stacksaga.trace-window.connector-port`
| `int`
| `0` _(disabled)_
| Optional dedicated port for `/stacksaga/*` endpoints. When set, a secondary connector is started on this port, and trace requests arriving on the main port receive `403 Forbidden`. Leave unset (`0`) to serve on the main application port.

| `stacksaga.trace-window.connector-ssl-bundle`
| `String`
| _(none)_
| The name of a Spring Boot SSL bundle (under `spring.ssl.bundle.*`) to enable HTTPS on `connector-port`. Only takes effect when `connector-port` is configured.

| `stacksaga.trace-window.connector-event-loop-threads`
| `int`
| `1`
| *(WebFlux only)* Number of Netty event-loop threads allocated to the secondary server started on `connector-port`. Minimal default to save resources on admin ports.

| `stacksaga.trace-window.allow-private-network`
| `boolean`
| `true`
| Whether to emit the `Access-Control-Allow-Private-Network: true` response header on CORS preflight and trace responses. Enables modern browsers (e.g. Chrome, Edge) running the public TraceWindow console (`https://trace.stacksaga.org`) to communicate with local or private-network microservices without triggering Private Network Access (PNA) blocks.
|===

[IMPORTANT]
====
Startup validation enforces that when `enable-api=true` and `secure-api=true`, `stacksaga.trace-window.access-token` must be provided. The application will fail fast at startup if the token is missing.
====

'''

== Configuration Examples

=== 1. Local Development Mode (Security Disabled)

Ideal for rapid local development on `http://localhost:8080` without generating tokens or logging into GitHub:

[source,yaml]
----
stacksaga:
  trace-window:
    enable-api: true
    secure-api: false
----

=== 2. Standard Production Mode (Main Port)

Uses dual-token security on the default microservice port:

[source,yaml]
----
stacksaga:
  trace-window:
    enable-api: true
    secure-api: true
    access-token: ${STACKSAGA_ACCESS_TOKEN}
----

=== 3. Dedicated Admin Connector Port (HTTP)

Exposes the `/stacksaga/*` trace endpoints exclusively on port `8787`. Calls to `/stacksaga/*` on the main application port will be rejected with `403 Forbidden`:

[source,yaml]
----
server:
  port: 8080

stacksaga:
  trace-window:
    enable-api: true
    secure-api: true
    access-token: ${STACKSAGA_ACCESS_TOKEN}
    connector-port: 8787
----

=== 4. Dedicated Connector Port with HTTPS (SSL Bundle)

Binds the secondary connector port `8787` to an independent SSL certificate declared via Spring Boot 3 SSL Bundles:

[source,yaml]
----
server:
  port: 8443

spring:
  ssl:
    bundle:
      jks:
        trace-connector-cert:
          keystore:
            location: classpath:admin-keystore.p12
            password: changeit
            type: PKCS12

stacksaga:
  trace-window:
    enable-api: true
    secure-api: true
    access-token: ${STACKSAGA_ACCESS_TOKEN}
    connector-port: 8787
    connector-ssl-bundle: trace-connector-cert
----

[TIP]
====
The main application server port (e.g. `8443`) and the connector port (`8787`) can use completely different SSL certificates and keystores.
====

=== 5. Custom Netty Threads (WebFlux Only)

For reactive services expecting high-frequency automated dashboard polling:

[source,yaml]
----
stacksaga:
  trace-window:
    enable-api: true
    secure-api: true
    access-token: ${STACKSAGA_ACCESS_TOKEN}
    connector-port: 8787
    connector-event-loop-threads: 2
----

'''

[[gateway-routing-examples]]
== Gateway Routing Examples

In xref:stacksaga-trace-window.adoc#gateway_mode[Gateway Mode], your API Gateway or reverse proxy intercepts incoming requests targeted at `{host:port}/{service-name}/{api-path}`, strips the service prefix, and forwards the call to the target internal microservice instance.

Here are concrete production routing configurations:

=== Spring Cloud Gateway

Configure route matching and path prefix stripping:

[source,yaml]
.gateway-application.yml
----
spring:
  cloud:
    gateway:
      routes:
        # Route for Order Service TraceWindow Connector
        - id: order-service-trace-window
          uri: lb://ORDER-SERVICE
          predicates:
            - Path=/order-service/stacksaga/**
          filters:
            # Strips the /order-service prefix before forwarding to the microservice
            - StripPrefix=1

        # Route for Payment Service TraceWindow Connector
        - id: payment-service-trace-window
          uri: lb://PAYMENT-SERVICE
          predicates:
            - Path=/payment-service/stacksaga/**
          filters:
            - StripPrefix=1

      # Enable CORS for the TraceWindow web console
      globalcors:
        cors-configurations:
          '[/**]':
            allowedOrigins: "https://trace.stacksaga.org"
            allowedMethods:
              - GET
              - POST
              - OPTIONS
            allowedHeaders:
              - Authorization
              - Content-Type
----

=== Nginx Reverse Proxy

Strip the service identifier prefix using a regex rewrite rule and pass through the authorization headers:

[source,nginx]
.nginx.conf
----
http {
    # Upstream definition for your microservices
    upstream order_service_upstream {
        server order-service-internal.local:8081;
    }

    upstream payment_service_upstream {
        server payment-service-internal.local:8082;
    }

    server {
        listen 443 ssl;
        server_name api.mycompany.com;

        # SSL configuration...

        # Order Service TraceWindow Route
        # Rewrites /order-service/stacksaga/* -> /stacksaga/*
        location ~ ^/order-service/(stacksaga/.*)$ {
            proxy_pass http://order_service_upstream/$1$is_args$args;

            # Forward client and host headers
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;

            # Ensure Authorization header (Bearer User_Token) is preserved
            proxy_pass_header Authorization;

            # TraceWindow CORS headers
            add_header 'Access-Control-Allow-Origin' 'https://trace.stacksaga.org' always;
            add_header 'Access-Control-Allow-Methods' 'GET, POST, OPTIONS' always;
            add_header 'Access-Control-Allow-Headers' 'Authorization, Content-Type' always;

            # Handle pre-flight OPTIONS requests
            if ($request_method = 'OPTIONS') {
                add_header 'Access-Control-Allow-Origin' 'https://trace.stacksaga.org' always;
                add_header 'Access-Control-Allow-Methods' 'GET, POST, OPTIONS' always;
                add_header 'Access-Control-Allow-Headers' 'Authorization, Content-Type' always;
                add_header 'Access-Control-Max-Age' 1728000;
                add_header 'Content-Type' 'text/plain charset=UTF-8';
                add_header 'Content-Length' 0;
                return 204;
            }
        }

        # Payment Service TraceWindow Route
        location ~ ^/payment-service/(stacksaga/.*)$ {
            proxy_pass http://payment_service_upstream/$1$is_args$args;
            proxy_set_header Host $host;
            proxy_pass_header Authorization;
        }
    }
}
----

=== Kubernetes Ingress (ingress-nginx)

When deploying on Kubernetes with the **ingress-nginx** controller, use path rewriting annotations:

[source,yaml]
.order-service-trace-ingress.yaml
----
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: order-service-trace-ingress
  namespace: stacksaga-apps
  annotations:
    # Rewrite /order-service/stacksaga/(.*) to /stacksaga/$1
    nginx.ingress.kubernetes.io/rewrite-target: /stacksaga/$1
    nginx.ingress.kubernetes.io/enable-cors: "true"
    nginx.ingress.kubernetes.io/cors-allow-origin: "https://trace.stacksaga.org"
    nginx.ingress.kubernetes.io/cors-allow-methods: "GET, POST, OPTIONS"
    nginx.ingress.kubernetes.io/cors-allow-headers: "Authorization, Content-Type"
spec:
  ingressClassName: nginx
  rules:
    - host: api.mycompany.com
      http:
        paths:
          - path: /order-service/stacksaga/(.*)
            pathType: ImplementationSpecific
            backend:
              service:
                name: order-service
                port:
                  number: 8081
----

== Connector Endpoints Reference

When `stacksaga.trace-window.enable-api=true`, the connector automatically registers and serves the following REST endpoints:

[cols="1,2,4", options="header"]
|===
| HTTP Method | Path Pattern | Purpose & Description

| `GET`
| `/stacksaga/api/v1/welcome`
| **Handshake & Health Probe:** Called by TraceWindow to verify service reachability, inspect service instance ID, validate tokens, and confirm project read permissions.

| `GET`
| `/stacksaga/api/v1/transaction`
| **Transaction Trace Query:** Retrieves comprehensive saga trace data for a given `transactionId`, including step execution nodes, execution state, timestamps, and error diagnostics.
|===

=== Request Headers

* `Authorization: Bearer <User_JWT_Token>`: Supplied by the TraceWindow web console to identify the active operator.
* `X-Timezone: <Timezone_Offset>`: (e.g., `+08:00`) Passed by TraceWindow to format all returned timestamps according to the operator's local timezone.

'''
